# Melhorias a aplicar neste plugin — fila do `/review`

> **Dono:** stakeholder. Só no repositório-fonte do plugin. Escreva cada item como **sintoma**, não como solução.

## Abertas
- Com QA eu preciso que ele faça a leitura das histórias (se tiver dúvida fala com o PO) junto com a análise do Protótipo funcional para montar os cenários de testes funcionais do Sprint; Importante que os testes possam também ser regressivos conforme o impacto de uma tarefa no processo funcional
- O QA deve ser capaz de realizar um teste funcional utilizando o plugin do Navegador Chrome para realizar os testes e identificar erros e GAPS registrando para correção
- Isso deve ocorrer a cada sprint, ou seja, na planning o QA deve já mapear os cenários funcionais que serão executados por tarefa e na entrega das tarefas pelo dev executá-los, usar o mesmo conceito de histórias aprovadas para o sprint para os cenários a testar no Sprint
- Adicionar um comando do QA para criar todos os cenários de testes sobre a documentação e protótipo do sistema como também de rodar cenários de testes único, grupo ou todos
- Os erros e gaps encontrados nos cenários de testes entram no Backlog para entrarem no próximo sprint
- Lembre-se de otimizar os gastos de tokens se identificar que alguma tarefa pode rodar pelo operator
